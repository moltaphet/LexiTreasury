# Final audit of the 171 skipped legacy scenarios

This audit was checked against the original test bodies in `tests/test_lexitreasury.py`, `tests/direct/test_adversarial.py`, `tests/direct/test_consensus_hardening.py`, and `tests/direct/test_treasury_lifecycle.py`. The old test bodies were retained; their test-only diffs add skip markers, while the adversarial, consensus, and lifecycle files have now been rewritten against the unified grant ABI and run. The 708-line deletion in the preceding diff was in `README.md`, not in these test files.

## Count and disposition

| Disposition of the original 171 test cases | Count |
| --- | ---: |
| Directly mapped to an active unified-contract test | 113 |
| Rewritten against the unified ABI and run (includes two core GitHub commit-error and one over-cap clipping case) | 56 |
| Obsolete contract-level status-filter assertions | 2 |
| Total | 171 |

The 113 direct mappings are the 118 core cases after separating three rewritten scenarios and two obsolete status-filter assertions. The 53 cases from the formerly skipped adversarial, consensus, and treasury suites were rewritten and are active. Two parameter cases rewrite the legacy commits-404 and commits-500 scenarios; the third rewrite changes tier-cap clipping into rejection of the already-committed full milestone plan.

The contract no longer exposes `get_proposals_by_status`: collection access is bounded by `get_grants(offset, limit)`. The old invalid-filter assertion has no contract call path, and the old approved-status filter assertion belongs to client-side filtering over fetched grant pages. This does not remove grant status data; each grant page includes the state. These two assertions are classified obsolete at the contract-ABI layer, with that filtering limitation recorded as a remaining coverage gap.

## Remaining gaps and limitations

- No Studio Dev or live-network validator run was performed, per instruction. `direct_vm.run_validator()` covers local leader/validator agreement and divergence, not actual network consensus or reset behavior.
- The two old status-filter contract assertions are obsolete at the contract API level. Clients must fetch bounded `get_grants` pages and filter those records locally; there is no contract-side indexed status query.
- The direct test harness verifies internal reserve, grant-escrow, released-total, and claimable invariants. It does not inspect the real deployed native-token balance; no deployment or transaction was made.
- The original core-suite test bodies remain skipped because they invoke the removed proposal ABI. The 113 directly mapped behaviors are exercised by named active replacements; only the two status-filter cases lack an equivalent contract-call assertion.
